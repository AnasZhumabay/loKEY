# Формат резервной копии `.lokeybackup` v1

Одиночный файл. Открытый заголовок (27 байт) служит AAD для всех записей:

| Поле | Размер | Значение |
|---|---|---|
| magic | 4 | `LKBK` |
| version | 2 (BE) | `1` |
| kdf | 1 | `1` = PBKDF2-HMAC-SHA256 |
| rounds | 4 (BE) | ≥ 600 000 в приложении |
| salt | 16 | случайная |

Далее записи `[UInt32 BE длина][AES-256-GCM combined]`. AAD записи = заголовок ‖ UInt32 BE индекс.
Запись 0: JSON-манифест `{formatVersion, createdAt, appVersion, device, cases[], files[], skippedLockedCases[]}`.
Записи 1..N: содержимое файлов в порядке `files[]` (sha256 каждого сверяется после расшифровки).

Ключ = PBKDF2(фраза, salt, rounds), 32 байта; фраза и ключ нигде не хранятся.

Что внутри: хранилище не отдаёт сырой шифртекст, поэтому файлы ОТКРЫТЫХ кейсов расшифровываются в памяти и перешифровываются ключом из фразы. Ключи кейсов в архив не попадают. Закрытые кейсы пропускаются и перечислены по имени.
Восстановление создаёт НОВЫЕ кейсы с новыми ключами. Потерянную фразу восстановить нельзя.
