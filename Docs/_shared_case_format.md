# Общий кейс: формат обёрнутого ключа (контракт 1.3.0)

У кейса свой случайный секрет (20 байт). Каждый участник хранит СВОЮ обёрнутую копию; сервер видит только blob.

    blob      = 0x01 || AES-256-GCM.combined(nonce12 || ciphertext || tag16)
    plaintext = секрет кейса (20 байт)
    wrapKey   = HKDF-SHA256(ikm = X25519(моя личность, личность контакта), salt = SHA256(caseId),
                            info = "lokey.sharedcase.wrap.v1", 32 байта)
    AAD       = UTF-8("caseId|inviterId|inviteeId")

- Общий секрет X25519 знают только двое; сервер его не получает, значит секрет кейса не раскрывает.
- Подмена caseId, отправителя или получателя ломает тег GCM (`wrongKey`).
- Приглашать и отзывать может только владелец; выдаются роли editor и viewer. Роль «Просмотр» соблюдается приложением, не криптографией.
- Отзыв доступа не стирает то, что человек уже видел. Нужна смена ключа (`rotateKeyAfterRevoke`, TODO: требует бэкенда).
- Отказ от приглашения в контракте 1.3.0 не предусмотрен: приглашение скрывается локально.
- Шов к чату: `ChatKeyAgreement.sharedSecret(withContact:)` должен реализовать ChatRepositoryImpl. В мок-режиме работает `DemoKeyAgreement` (НЕ защита, только демо).
- Код: `Core/Shared/SharedCaseWrap.swift`.
