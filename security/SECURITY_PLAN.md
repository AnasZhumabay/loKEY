# loKEY: план по безопасности и шифрованию (моя часть диплома)

Репозиторий: https://github.com/AnasZhumabay/loKEY
Стек: iOS (Swift/SwiftUI) + бэкенд FastAPI/Postgres. Принцип: zero-knowledge, сервер хранит только шифртекст.

Моя зона ответственности (договорённость с командой): шифрование, управление ключами, аутентификация, безопасность бэкенда и API, модель угроз, тестирование безопасности. Все задачи из `Docs/CRYPTO.md` (ветка `backend`, контракт 1.3.0) входят в мою часть.

Статусы: `[ ]` не начато, `[~]` в работе / частично, `[x]` готово.

# Часть B. Шифрование (по `Docs/CRYPTO.md`, ветка `backend`)

Источник: `Docs/CRYPTO.md` («руководство для разработчика шифрования»). Метки в нём: «факт» (проверено автором по коду), «предложение» (решение не принято, согласовать с командой), «не проверено». Номера строк кода взяты оттуда и мной ещё не сверялись.

## Золотые правила (из CRYPTO.md, кратко)
1. Ключи и открытые данные не покидают устройство. Если для фичи «нужно отправить ключ на сервер», фича спроектирована неправильно.
2. Только CryptoKit / CommonCrypto. Nonce для AES-GCM генерирует CryptoKit, руками не задавать.
3. Каждый новый формат начинается с байта версии (или поля `v`); старые данные продолжают читаться.
4. AAD связывает шифртекст с контекстом (id кейса / файла / отправителя).
5. Не ослаблять защиту молча: нет ключа значит ошибка, а не «продолжим без шифрования».
6. Не логировать ключи, секреты, фразы, открытый текст, даже в `#if DEBUG`.
7. Каждая схема идёт с тестом: круг шифрования, неверный ключ, подмена шифртекста, подмена AAD; для новых форматов тестовые векторы.

## Процесс работы
- Код пишу я (Windows, собрать Swift нельзя), друг на Mac запускает `xcodebuild test -scheme loKEY -destination 'platform=iOS Simulator,name=iPhone 15'` и присылает вывод, я исправляю.
- Основа: ветка `backend`; на каждую задачу отдельная ветка (например `security/p0-shared-case`); в `main` и `backend` напрямую не пушить. В какую ветку делать PR: уточнить у команды.
- Маленькие шаги: одна задача равна небольшому набору изменений.
- Для каждой задачи: короткий дизайн в `security/` (форматы, AAD, версия, поведение при ошибке), код, XCTest-тесты, прогон на Mac, PR.
- Чек-лист перед PR (раздел 5 CRYPTO.md): `⌘U` зелёный; у нового формата байт версии; нет секретов в логах; секреты только в Keychain; обновлены `Docs/_*_format.md`; `AppConfig` (`useMocks`, `apiBaseURL`) не попал в коммит.
- Изменения контракта API только добавлением (MINOR, 1.4.0): `loKEY/Contract/*.swift`, `Docs/BACKEND_CONTRACT.md`, `Docs/backend-kit/openapi.yaml`, затем сервер (сервер делает Амир).
