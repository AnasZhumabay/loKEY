# loKEY: план по безопасности и шифрованию (моя часть диплома)

Репозиторий: https://github.com/AnasZhumabay/loKEY
Стек: iOS (Swift/SwiftUI) + бэкенд FastAPI/Postgres. Принцип: zero-knowledge, сервер хранит только шифртекст.

Моя зона ответственности: шифрование, управление ключами, аутентификация, безопасность бэкенда и API, модель угроз, тестирование безопасности.

## Этап 1. Модель угроз
- [ ] Активы: содержимое файлов, ключи кейсов, recovery-фраза, vault key, токены, метаданные
- [ ] Акторы: внешний атакер, скомпрометированный сервер/админ, вор устройства, вредоносное приложение, MITM
- [ ] Границы доверия: устройство / сеть / сервер / облачный бэкап (iCloud)
- [ ] STRIDE по основным потокам: регистрация, вход, создание кейса, загрузка файла, шаринг, чат, бэкап, восстановление
- [ ] Что сервер видит (метаданные: размеры, время, число кейсов, audit, security-events)

## Этап 2. Раздел «Криптография»
- [ ] Описать алгоритмы: AES-256-GCM, HKDF-SHA256, PBKDF2-HMAC-SHA256 (600 000 раундов), SHA-256
- [ ] Формат шифртекста: nonce(12) || ciphertext || tag(16)
- [ ] Иерархия ключей: секрет кейса -> HKDF -> ключ кейса; vault key в Keychain; recovery wrap
- [ ] Обоснование выбора алгоритмов и параметров
- [ ] Энтропия recovery-фразы (какой словарь, сколько бит)
- [ ] Чат: ChatCrypto, проверка forward secrecy, подмена ключей, номер безопасности
- [ ] Ограничения: vault key не синхронизируется между устройствами, сброс пароля не восстанавливает ключи

## Этап 3. Хранение ключей и защита на клиенте
- [ ] Keychain: ThisDeviceOnly, биометрия (biometryCurrentSet)
- [ ] DuressPIN, DecoyVault, AttemptTracker, CaptureGuard, PrivacyCover
- [ ] Локальные кэши зашифрованы и исключены из бэкапа
- [ ] Бэкапы (локальные, iCloud): формат и защита

## Этап 4. Безопасность бэкенда и API
- [ ] Аутентификация: argon2id, непрозрачные токены (в БД SHA-256), ротация refresh, TOTP
- [ ] Rate limiting (сейчас в памяти, нужен Redis при нескольких репликах)
- [ ] Проверка целостности блобов (X-Content-SHA256), If-Match / 409
- [ ] HTTPS (Caddy, Let's Encrypt), заголовки, CORS
- [ ] Секреты и .env, конфигурация прод/dev
- [ ] Сервер никогда не получает ключи, секреты кейсов, recovery-фразу, vault key
